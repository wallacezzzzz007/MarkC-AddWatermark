# v0.4 - Batch Export, Output Folder, And Naming Rules

Status: Completed

## Mode 0 - Intake

PM:

- v0.4 turns the single-image proof into a usable batch workflow.
- Metadata and saved templates remain v0.5.

Architect:

- Reuse the v0.3 Rust renderer/exporter.
- Add batch DTOs, output folder override, naming rules, and per-file results.
- Prefer a single command returning per-file results for v0.4; event streaming can come later if needed.

QA-Pre:

- Batch export must not stop on individual file failures.
- Filename collisions must append numbers by default.
- Custom output folder must not mutate sources.
- UI must stay responsive enough for typical batches.

UI/UX:

- Right pane should expose output folder picker, naming rule selection, custom prefix, and batch export status.
- Keep the flow compact and clearly selected as batch export.

Main Chat:

## Mode 1 - Proposal

PM:

- Recommended task: export all imported images using the current watermark, output folder setting, and selected naming rule.
- Why now: after single-image export, batch output is the main practical user value.
- Acceptance criteria:
  - User can batch export all imported real images.
  - User can pick an output folder.
  - If no folder is picked, outputs go to `Watermark export` under each source folder.
  - Naming rules work:
    - `{name}_watermark.{ext}`
    - `watermark_{name}.{ext}`
    - `watermark_{index}.{ext}`
    - `{prefix}_{index}.{ext}`
  - Collisions append a number.
  - Per-file success/failure is visible.
  - Failed files do not stop the whole batch.

Architect:

- Design impact:
  - Extend v0.3 single-image exporter into a batch-capable export flow.
  - Use one `export_batch` command returning final results.
  - Emit lightweight progress events in Rust, but keep full job/cancel architecture out of v0.4.
- IPC:
  - `export_batch(request) -> BatchExportResult`
  - Event: `batch_export_progress`

QA-Pre:

- Key risks:
  - Duplicate basenames and collision behavior.
  - Missing source files should fail per file, not abort batch.
  - Output folder cancellation and permission failures.
  - QA fixture/fake paths must not be exported.
  - UI should not imply templates or metadata are available.

UI/UX:

- Right pane owns v0.4 batch export controls:
  - output folder picker
  - naming rule selector
  - custom prefix input
  - collision note
  - progress/status
  - primary `Export N Images` button
- Left import queue shows per-file result labels after export.

## Mode 2 - Execution

  - Four naming rules.
  - Collision-safe append-number.
  - Per-file result display.
  - No metadata/templates/cancel.

Architect:

- Implementation notes:
  - Added frontend `OutputRules`, `BatchExportRequest`, `BatchExportResult`, and item result types.
  - Added `useExportStore` for output rules and batch status/results.
  - Extended Rust export DTOs with `OutputRules`, `NamingRule`, batch request/result, and progress event.
  - Registered `export_batch` command.
  - Kept v0.3 renderer/exporter as the core per-file implementation.
- IPC design:
  - Frontend calls `export_batch`.
  - Rust loops file-by-file and emits `batch_export_progress` after each item.
  - Current frontend relies on final result; progress-event subscription can be wired in v1 if large-batch UX requires it.

QA-Pre:

- Must-not-break list:
  - Source files are not mutated.
  - Individual failures do not abort the batch.
  - QA fixture assets are blocked from export.
  - Collision filenames append `-2`, `-3`, etc.
  - Empty watermark blocks export.
