# v0.1 - App Shell And Import Preview

Status: Completed

## Mode 0 - Intake

PM:

- Confirm v0.1 only covers the trusted intake layer: app shell, image import, queue, preview, status, and source safety.
- Supported image formats are `.jpg`, `.jpeg`, and `.png`.
- Valid imports continue even when some files fail.

Architect:

- Scaffold Tauri + React + TypeScript + Vite.
- Frontend owns UI state, selected image, preview rendering, and visible errors.
- Rust owns filesystem access, folder traversal, format filtering, and image dimension reads.
- No watermark rendering, metadata editing, or export logic in v0.1.

QA-Pre:

- Verify unsupported/corrupt files fail gracefully.
- Verify non-ASCII paths and uppercase extensions.
- Verify source files are read-only references.
- Verify large previews do not block the whole UI.

UI/UX:

- Use a serious desktop utility layout.
- Left pane: import queue.
- Center pane: selected image preview.
- Right pane: disabled future controls so the product shape is visible without pretending v0.2 work is done.

Main Chat:

- Build v0.1 end to end, then run QA before moving to v0.2.

## Mode 1 - Proposal

PM:

- Recommended task: build a Tauri desktop intake shell that imports one image, multiple images, or a folder; shows valid and skipped files; and previews selected valid images.
- Why now: every later watermark and export workflow depends on trustworthy image intake.
- Acceptance criteria:
  - App launches as a desktop shell.
  - User can import one image, multiple images, and a folder.
  - Queue displays filename, format, dimensions, and status.
  - Selecting a ready item shows a preview.
  - Unsupported or corrupt files are reported without stopping valid imports.
  - Source files are never modified.

Architect:

- Design impact: establish the React/Rust boundary early.
- Modules affected:
  - `src/App.tsx`
  - `src/App.css`
  - `src/components/*`
  - `src/stores/libraryStore.ts`
  - `src/types/image.ts`
  - `src/lib/ipc.ts`
  - `src-tauri/src/commands/import.rs`
  - `src-tauri/src/domain/image_asset.rs`
  - `src-tauri/src/processing/image_info.rs`
- IPC plan:
  - `import_files(paths: Vec<String>) -> ImportResult`
  - `import_folder(path: String, recursive: bool) -> ImportResult`
  - `get_image_info(path: String) -> Result<ImageAsset, ImageImportError>`

QA-Pre:

- Risks:
  - Preview path handling across Tauri IPC.
  - Large images freezing the WebView.
  - Corrupt files passing extension checks.
  - Unsupported files silently disappearing.
  - Duplicate imports causing confusing queue state.
- Required tests:
  - Single JPG import.
  - Single PNG import.
  - Multi-image import.
  - Folder import with mixed files.
  - Unsupported/corrupt file handling.
  - Non-ASCII paths.
  - Source modified timestamp remains unchanged.

UI/UX:

- Three-pane desktop layout:
  - Left: fixed import queue with compact buttons and useful empty state.
  - Center: neutral preview canvas with selected image fit to view.
  - Right: inspector-style future controls disabled for v0.2+.

QA-Post:

- Validation plan:
  - Run TypeScript build.
  - Run Rust/Tauri build checks.
  - Launch dev app.
  - Exercise import and preview flows.
  - Confirm source files are not written.

Main Chat:

- Final proposed next step: implement v0.1 exactly to this scope, then record QA findings before starting v0.2.

## Mode 2 - Execution

PM:

- Final scope is import and preview only.

Architect:

- Tauri commands return typed DTOs and do not mutate source files.
- Frontend wraps IPC calls and keeps state in a small library store.

QA-Pre:

- Must-not-break list:
  - Do not overwrite or write beside source files.
  - Do not crash on partial import failures.
  - Do not hide skipped files.

UI/UX:

- Future watermark/export controls are visible but disabled.

  - Added React components:
