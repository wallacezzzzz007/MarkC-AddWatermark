# v0.2 - Basic Text Watermark Editor

Status: Completed

## Mode 0 - Intake

PM:

- v0.2 adds the interactive text watermark editing loop.
- No final image export in this version.
- The user should be able to tune one watermark on the selected preview image.

Architect:

- Frontend owns the live editor state for v0.2.
- Rust IPC is not required until final rendering/export in v0.3.
- Watermark position should be stored as relative coordinates so later export can apply it across image dimensions.

QA-Pre:

- Preview placement must not jump when switching images or resizing.
- Dragging must clamp the watermark inside the image bounds.
- Empty or long text should not break layout.

UI/UX:

- Right pane becomes real controls for text, size, color, opacity, and anchors.
- Center pane becomes a simple editor surface with a draggable watermark overlay.

## Mode 1 - Proposal

PM:

- Recommended task: make a selected imported image editable with a text watermark preview.
- Why now: this proves the user's main customization loop before committing Rust export rendering.
- Acceptance criteria:
  - User can enter watermark text.
  - Default watermark resembles the sample: white, bottom center.
  - User can adjust size, color, and opacity.
  - User can drag the watermark in the preview.
  - User can choose anchor presets.
  - Position is stored in relative coordinates.

Architect:

- Design impact: add an editor state slice and make preview overlay aware of image frame bounds.
- Modules affected:
  - `src/types/watermark.ts`
  - `src/stores/editorStore.ts`
  - `src/components/PreviewPane.tsx`
  - `src/components/ControlPane.tsx`
  - `src/App.tsx`
  - `src/App.css`
- IPC plan:
  - No new IPC required in v0.2.

QA-Pre:

- Risks:
  - Preview overlay coordinates differ from later export math.
  - Drag can place text outside the image.
  - Long text can overflow controls or preview.
  - Empty text creates an invisible but confusing drag target.
- Required tests:
  - Default sample position.
  - Text input updates preview.
  - Size, color, opacity controls update preview.
  - Anchor presets update relative coordinates.
  - Drag updates coordinates and clamps within bounds.
  - No selected image keeps controls safe.

UI/UX:

- Keep the desktop utility feel.
- Use compact controls, ranges, and swatches.
- Make the watermark draggable only on the selected image, not over the whole preview canvas.

QA-Post:

- Pending.

## Mode 2 - Execution

PM:

- Final scope stayed editor-only. No export, no filesystem writes, and no Rust renderer were added.

Architect:

- Implementation notes:
  - Added `WatermarkDraft` and `WatermarkAnchor` types.
  - Added `useEditorStore` for watermark text, color, opacity, size percentage, relative X/Y, and anchor.
  - Kept `libraryStore` isolated to imports and selected image state.
  - `PreviewPane` now measures the displayed image frame with `ResizeObserver`.
  - Drag converts pointer coordinates to image-relative `0..1` coordinates.
  - Manual drag switches anchor state to `center`; preset buttons restore named anchors.
- IPC design:
  - No new IPC added in v0.2.

QA-Pre:

- Must-not-break list:
  - No source mutation.
  - No export path.
  - Preview overlay positioned against rendered image frame, not full checkerboard stage.
  - Empty text hides the overlay.
  - Coordinates are stored as relative values.

UI/UX:

- UI details:
  - Right pane now has enabled text, size, opacity, color, and anchor controls.
  - Default watermark remains `@bntxx_`, white, semi-transparent, bottom center.
  - Overlay uses a handwriting-style font stack, subtle outline, and move cursor.
  - Output section remains disabled for v0.3.
